# BGMの一時停止状態の復元

## 報告された条件
同一ステージで一時停止して保存し、そのままロードするとBGMが停止しない。
リセット後にロードした場合は停止する。

## 調査
SceneManagerは同じシーンへのロードでは既存シーンを再利用する。
旧BgmManager::RestoreStateはPlay→再生位置設定→Pauseの順。
SoundChannel::PauseはCheckSoundMemが再生中を返した場合だけ停止していた。
したがって「停止状態の復元」にも一度再生を開始し、その直後のバックエンド状態確認が必要だった。
ゲーム内の報告症状は未再現。実音声の単独テストでは旧処理も成功したため、
バックエンドのタイミングやウィンドウ・メニューとの相互作用を原因と断定しない。

## 今回の対処
- BgmManager: 読み込みと再生開始を分離。復元時は再生せず停止状態を準備し、
  音量・位置・フェード等を復元後、保存状態がPlayingの場合だけResumeする。
- ISoundChannel / SoundChannel / ChannelManager: PreparePausedを追加。
  再生状態の問い合わせに依存せず、停止して再生位置と再開可能状態を設定。
- SoundChannel::Pause: 二重Pauseで再開可能状態を失わないようにする。
- セーブ形式の変更なし。

## 検証
--state-testsに、同じ管理オブジェクトへ繰り返し復元→Resume→Pause、
Paused復元でPlayを一度も呼ばないこと、Playing復元で保存位置から再開する検証を追加。
--bgm-backend-testsはmm2hackディレクトリから実行する実音声バックエンド用の任意テスト。
非表示ウィンドウ・音量0で同一セッション復元とRelease後の復元を比較し、
実際のチャンネル停止・再開を確認する。bgm-backend-test.txtへ結果を出力する。

ゲーム内では、保存直後ロード、再開→再ポーズ、同じデータの連続ロード、
リセット後ロードを確認する必要がある。

## 実行結果
- Debug x64ビルド成功。
- --state-tests: 終了コード0。
- --bgm-backend-tests: 終了コード0。同一セッション2回・Release後1回ともplaying=0、再開・再ポーズ成功。
- 報告されたゲーム内メニュー操作での再現／解消確認は未実施。

更新版で報告症状が再現しないこと、およびプレイ中に違和感がないことを確認済み。
