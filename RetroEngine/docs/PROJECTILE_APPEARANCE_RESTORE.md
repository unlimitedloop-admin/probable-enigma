# 弾グラフィックのロード復元対応

## 原因と実装
EntityStateFactory が全 Projectile を EffectsSprite（水しぶき）で復元していた。
弾の見た目を永続ID ProjectileAppearance（uint16）として保存し、通常生成と
ロードの両方で IStageAssetProvider::ProjectileSprite を使って画像を取得する。

IDは当たり判定レイヤー、武器ID、実行中の画像ハンドルと独立。
既存IDは PlayerBuster=1 / EnemyEnergy=2。0は無効。
未知ID・未ロード画像を別画像に置き換えない。ロード時は復元失敗、
通常生成時は生存しない弾として扱う。
画像ハンドルは保存しないので、再起動や読み込み順の変更にも依存しない。

## 変更箇所
- SpawnProjectileCommand.h: 永続IDと既知ID検証を定義。生成要求の画像ハンドルを見た目IDへ置換。
- IStageAssetProvider.h: 通常生成と復元が共有する画像解決APIを追加。
- AttackActionState.cpp/.h / PlayerEntity.cpp: 自キャラ弾にPlayerBusterを指定し、攻撃状態の不要な画像ハンドルを削除。
- EnemyEntity.cpp: 敵弾にEnemyEnergyを指定。
- AbstractActionPhase.cpp: 弾生成へステージの画像プロバイダーを渡す。
- ProjectileEntity.cpp/.h: 見た目IDの保存・検証・復元。画像の再解決、描画サイズの再計算。
  弾かれた画像の可否も当たり判定ではなく見た目IDから決める。
- EntityStateFactory.cpp: 固定EffectsSprite割り当てを廃止。
- SaveStateTests.cpp: 画像ハンドルを変更した環境での復元、表示状態の一致、
  当たり判定と見た目の独立性、未知ID・欠落画像・旧版拒否を検証。

## セーブ互換性
Projectileのcomponent versionを4から5へ更新。
version 4以前の弾を含むセーブは、対象データの事前検証で拒否する。
曖昧な推測移行は行わない。弾レコードを含まないセーブはこの変更だけでは無効にならない。
ゲーム確認には更新版で新たにセーブを作成する。

## 今後の敵・弾種追加
1. 同じ画像シートを使う新しい敵は既存の見た目IDを再利用できる。
2. 新しいシートには未使用の固定IDを追加し、既知ID検証とProjectileSpriteの対応を追加する。
   IDは並べ替え・再利用しない。
3. 生成要求にIDを設定し、タイル番号・描画方式・アニメーションを指定する。
4. 新IDを回帰テストの一覧に加える。通常生成と復元に別々の画像選択処理を追加しない。
5. 複合描画や弾かれた画像の配置が異なる場合は対応する描画仕様も追加する。
   この対応は未知の描画仕様を自動生成するものではない。

## ゲーム内での受け入れ確認
- 敵弾が飛行中にポーズ→セーブ→ロードし、ロード直後の画像・位置・再開後の動きを確認。
- 自キャラ通常弾、チャージ1/2、左右向き、弾かれた弾でも同様に確認。
- 水しぶき・爆発・チャージ粒子が混在しても、画像が入れ替わらないことを確認。
- 別シーンを経由したロード、アプリ再起動後のロードでも確認。
