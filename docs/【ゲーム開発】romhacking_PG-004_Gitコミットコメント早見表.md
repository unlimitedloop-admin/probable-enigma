✅ **ポイント**

*   先頭は動詞の過去形で統一（Gitの慣習）
*   簡潔に「何を」「なぜ」を書く
*   必要なら `(WIP)` や `[#issue-number]` を追加

***

**さらに便利なもの**：

*   **Added / Implemented** → 新機能やクラス追加
*   **Refactored / Reorganized** → コード整理や構造変更
*   **Changed / Modified** → 挙動や設定の変更
*   **Fixed** → バグ修正

## ✅ **日本語 → 英語コミットメッセージ早見表**

### **追加系**

*   「〇〇を追加」  
    → `Added [feature/component]`  
    例：`Added player entity base class`

*   「〇〇のサポートを追加」  
    → `Added support for [functionality]`  
    例：`Added support for multiple tile layers`

***

### **実装系**

*   「〇〇を実装」  
    → `Implemented [feature/class/method]`  
    例：`Implemented collision detection logic`

*   「〇〇の初期バージョンを実装」  
    → `Implemented initial version of [feature]`  
    例：`Implemented initial version of animation system`

***

### **リファクタリング系**

*   「〇〇をリファクタリング」  
    → `Refactored [class/module]`  
    例：`Refactored BGTileMapProvider implementation`

*   「コードを整理」  
    → `Refactored code structure for [feature]`  
    例：`Refactored code structure for rendering pipeline`

***

### **再構成系**

*   「プロジェクト構成を整理」  
    → `Reorganized project structure`  
    例：`Reorganized directories for better maintainability`

***

### **変更系**

*   「〇〇の挙動を変更」  
    → `Changed behavior of [method/feature]`  
    例：`Changed logic for ground detection`

*   「設定を変更」  
    → `Changed default settings for [component]`  
    例：`Changed default tile size`

***

### **修正系**

*   「〇〇の不具合を修正」  
    → `Fixed bug in [feature/component]`  
    例：`Fixed bug in animation counter`

*   「〇〇の問題を解決」  
    → `Fixed issue with [logic/validation]`  
    例：`Fixed issue with collision detection`

***

✅ **使い方のコツ**

*   先頭は必ず動詞の過去形（Added, Implemented, Refactored, Fixedなど）
*   簡潔に「何を」「どんな目的で」を書く
*   必要なら `(WIP)` や `[#issue-number]` を追加
