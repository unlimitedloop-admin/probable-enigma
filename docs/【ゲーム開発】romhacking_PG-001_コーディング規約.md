### ✅ RetroEngine コーディング規約

#### **1. 基本方針**

- 本プロジェクトは C++20 標準に準拠する。
- Unicode文字セットを使用し、エントリポイントは `wWinMain` とする。
- ソースコードは明瞭かつ保守しやすいように設計することを重視する。
- 名前空間やクラスを用いたモジュール化を推奨する。

---

#### **2. ファイル構成と命名規則**

- `src/` フォルダ内に以下のディレクトリを作成し、各機能ごとに整理する：
  - `apps/`: ゲームプログラム本体 (`graphics`, `scenes`, `audio` など)
  - `config/`: 設定ファイルや定数の定義
  - `core/`: アプリケーション中枢機能 (WinAPI ハンドリング、ウィンドウプロシージャ)
  - `exceptions/`: 例外クラスとエラーハンドリング
  - `input/`: ユーザー入力の管理
  - `resources/`: リソースファイル (画像、音楽、データファイル)
  - `utils/`: ユーティリティ関数とヘルパークラス

##### **ファイル命名規則**

- **ソースファイル** (`.h` と `.cpp`): **PascalCase** で命名。
  - 例: `WindowManager.h`, `WindowManager.cpp`
- **リソースファイル** (`.png`, `.wav` など): 小文字スネークケースで命名。
  - 例: `background_music.wav`
- **ユーティリティ関数のみを定義するファイル:**
  - クラスとして実装する場合：**PascalCase** で命名（例：`FileLoader.h`, `FileLoader.cpp`）。
  - 純粋な関数群として提供する場合：**小文字スネークケース** で命名（例：`math_utils.h`, `math_utils.cpp`）。

---

#### **3. コードスタイル**

##### **3.1 インデントとスペース**

- インデント：**4スペース**（タブは禁止）
- ブロックの `{}` は常に改行して書く（例外なし）
  ```cpp
  if (condition)
  {
      // 処理
  }
  else
  {
      // 処理
  }
  ```

##### **3.2 命名規則**

- **クラス名**: `PascalCase` (`GameEngine`, `AudioManager`)
- **メンバ関数名**: `PascalCase` (`Initialize()`, `RenderScene()`)
- **メンバ変数**: `_` + `snake_case` (`_window_handle`, `_frame_rate`)
- **グローバル変数**: 全て大文字 + アンダースコア (`MAX_FPS`, `WINDOW_WIDTH`)
- **定数**: `k` + `PascalCase` (`kMaxPlayers`, `kDefaultVolume`)
- **名前空間**: 小文字 + アンダースコア (`core`, `graphics`)

---

#### **4. コード書式と構文**

- ヘッダーファイルにはインクルードガードを使用する（`#pragma once`）。
- 関数の引数と戻り値には `const` を適切に使用する。
- スマートポインタ (`std::unique_ptr`, `std::shared_ptr`) を優先して使用し、裸ポインタは必要な場合に限定する。
- `std::string` ではなく、`std::wstring` を使用する（Unicode対応のため）。
- `auto` は読みやすさを損なわない場合にのみ使用する。

---

#### **5. using に関する規則**

- **グローバル名前空間での ****`using namespace`**** は禁止。**
- **ヘッダーファイルでの ****`using`**** は禁止。**
- **関数内での ****`using`**** は許可。**
- **名前空間エイリアスの使用を推奨。**
- **明示的な ****`using`**** 宣言は許可。**

---

#### **6. コメントとドキュメンテーション**

- 各クラス、関数にはヘッダコメントを記載する。
- `///` を使用して Doxygen スタイルのコメントを推奨する。
- コード中の重要な処理には、適宜コメントを追加する。
- 特殊な処理や注意が必要な部分には `TODO`, `FIXME` などのタグを用いる。

##### **6-1. アノテーションコメントのタグ**

| 記法                 | 説明                  |
| ------------------ | ------------------- |
| `TODO`             | 未実装の機能や改善点を示す。      |
| `FIXME`            | 修正が必要なコードを示す。       |
| `NOTE`             | 特記事項や注意点を示す。        |
| `HACK`             | 一時的な回避策や不完全な実装を示す。  |
| `OPTIMIZE`         | パフォーマンス改善が必要な部分を示す。 |
| `REVIEW`           | コードレビューが必要な部分を示す。   |
| `DEPRECATED`       | 非推奨の機能やコードを示す。      |
| `WARNING`          | 注意が必要なコードを示す。       |
| `WIP` または `W.I.P.` | 作業中のコードを示す。         |

---

#### **7. ファイルコメント**

- **ヘッダーファイル (**`.h`**) には必ずファイルコメントを付ける。**
- **実装ファイル (**`.cpp`**) は大規模または重要な機能のみコメントを付ける。**
- コメント形式は `//` で統一し、視認性を良くするために `//==============================================================================` を使う。
- 作成日や更新日については、Git の履歴管理を利用するため、省略してもよい。

---

#### **8. エラーハンドリング**

- 例外を使用する場合は、`exceptions/` フォルダに定義したカスタム例外クラスを使用する。
- エラーメッセージは `std::wstring` 形式で統一する。
- DirectX 関連のエラーチェックには `HRESULT` を使用する。

---

#### **9. コードレビューとコミット規約**

- コミットメッセージは簡潔かつ明確にする：
  ```
  [core] Implemented Window Initialization
  [apps] Added Basic Rendering Loop
  [utils] Refactored File Loader Functions
  ```
- `main` ブランチへの直接コミットは禁止。プルリクエストを通してレビューを行うこと。

---

#### **10. グローバル変数に関する規則**

- グローバル変数の使用は**原則禁止**とする。モジュール間の依存性を曖昧にし、保守性とテスト性を著しく損なうため。
- ただし、**以下のケースに限り使用を許可する**：

| 用途        | 条件                                   | 実装例                                                        |
| --------- | ------------------------------------ | ---------------------------------------------------------- |
| 定数        | 値が固定で変更されない。グローバルスコープで共有したいもの。       | `inline constexpr int MAX_FPS = 60;`（`config/Constants.h`） |
| 読み取り専用構造体 | アプリケーション設定や初期化情報など、実行時に変更されないもの。     | `extern const GameSettings g_settings;`（書き換え禁止）            |
| シングルトン    | 明確なクラス設計のもとで、初期化・破棄・アクセスを一元管理している場合。 | `auto& logger = Logger::GetInstance();`                    |

- `extern` 変数での状態共有は**禁止**とし、代わりに **アクセサ関数（例：**`**）や **`\*\* クラス\*\* などで制御する。
- グローバル定数は、`config/Constants.h` 等の専用ファイルに `inline constexpr` で定義し、インクルードで利用すること。

##### **命名規則**

- グローバル変数：**全て大文字 + アンダースコア**（例：`WINDOW_WIDTH`, `MAX_FPS`）
- グローバル構造体インスタンス（読み取り専用）：接頭辞 `g_` + スネークケース（例：`g_settings`）

---

#### **11. リソースファイルの配置と読み込み規則**

- 実行時に使用するグラフィック・音楽・データ等のリソースは、`assets/` フォルダ以下に配置する。
- `src/resources/` はあくまで **開発中の素材の保管用** とし、**ビルド時に必要なものを ****\`\`**** にコピーして使用する**。
- コード上では、`src/` には一切依存せず、すべて `assets/` 経由でアクセスすること。
- 配布時には `src/` を含めず、`assets/` + 実行ファイルのみで構成することを推奨する。
